# Fetarute 首页内容大纲

> 状态：进行中的内容方向。用途：为首页文案、图片选择与后续页面拆分提供共同判断依据；本文件不替代真实服务器信息、规则或加入流程的正式发布。

## 已确认的方向

- Fetarute 成立于 **2017 年**。
- 首页首先是一篇介绍 Fetarute 的作品：让第一次到访的人理解这里是什么、为何以铁路为线索、它由怎样的社区建设而来。
- Fetarute 由三个子服务器组成；它们通过 **服连快线（Serverlink）**
  运营的联络线连成一个整体。这个事实是首页解释「铁路为何重要」的核心。
- 首页不承担玩法说明或服务器操作手册的职责；不写分区玩法细节、游戏命令、版本要求、客户端准备或服务器地址。
- 目前唯一有效、应在首页明确呈现的加入入口是
  **QQ 门户群**。它由「续行」PIDS 的首次到访帮助承接；Discord、X、在线申请及其他旧入口暂不作为加入方式宣传。
- 现有的「线路导视 → 到站确认 → 铁路实景」开场是首页叙事的起点；首屏抵达后应继续介绍这座世界，而不是转入建站技术说明。
- 首页的职责是用一段轻量、连续的叙事建立印象，再把深层内容交给独立页面。滚动可以保留旅程感，但不以公告、在线状态、完整玩家档案或玩法资料不断延长首页。
- 「同岸」就是首页的社群章节，不是通往另一段大型玩家展示的过场；「续行」则是短小的探索入口，负责把读者送往真实地图、Wiki 与当前有效的加入渠道。

## 首页的一句话定位

**Fetarute 是一个自 2017 年起持续建设、由服连快线连接三个子服务器、地点与人的 Minecraft 社区。**

这句话用于统一判断，不要求原样显示。文案应保持具体、克制，避免把仍待确认的运营状态、功能或加入条件包装成既成事实。

## 推荐阅读路径

```text
抵达 Fetarute
  → 看见铁路如何连接世界
  → 在三服汇轻量认识三个子服务器
  → 在同岸看见共同建设世界的人
  → 从续行前往真实地图、Wiki 或 QQ 门户群
```

首页的阅读目标到「产生兴趣并知道下一步在哪里」为止。完整玩家故事、社区活动、公告、在线状态与操作资料不在首页继续展开。

## 连续行程视觉语法

首页不是在末尾附加一张「访问总结」，而是以一段连续铁路行程串联抵达、世界、服务器与社群。服连快线在「同岸」完成叙事换乘，之后由湾岸支线承接玩家与探索方向。读者以原生滚动向下阅读；列车和线路只负责说明章节之间的关系，不替代内容本身。

### 无界连续构图

这不是 FurryGoods-Portal 那种把每段内容置于明确容器、再由壳层组织浏览的有界界面。Fetarute 首页应像穿过一张持续延展的平面铁路导视图：没有把整趟旅程框进画布的边线，线路可以从视窗外驶入、穿过内容之间的留白，再向下一段视窗外延伸。

- 每个 section 是内容上的章节，不是视觉上的封闭盒子；不为路线、列车或「本次到访」制造包住整段的外框。世界正文后的单一操作卡可以承接地图等明确行动，但不能把整段内容改造成卡片墙或独立应用面板。
- 服连快线负责抵达、世界与三服汇；湾岸支线从同岸接续社群与续行。视窗只是在这段路线中移动的观察窗口：向下滚动即是沿线路继续前进，而不是翻到一页新的站点画面。
- 列车的进度绑定文档的累计滚动位置，并在同一服务区段内保持方向与身份；同岸以可见的双车换乘完成线路交接，不能用隐藏、传送或无说明换色代替。
- 章节交界处以足够大的留白、线路转折和场景尺度变化来换气；不要以整齐的容器边缘、封闭背景块或浮层把上下内容切断。
- 「续行」出发厅是唯一有意的收束：它表示首页叙事在此告一段落，同时让线路继续驶向其他页面，而不把此前的行程改造成封闭的产品流程。

### 有选择地采用 Material Design 3 的交互语法

Material Design
3 在这里是**交互质量的参考**，不是首页的视觉皮肤或组件库。Fetarute 仍以铁路导视、扁平几何和无界连续构图建立身份；M3 只帮助可操作元素给出清楚、一致且可访问的反馈。

- 所有真实可操作元素（导航、语言与外观控制、公告条目、QQ 门户群入口）都应有可辨识的 enabled、hover、focused、pressed 与 disabled 状态。状态变化只改变局部色层、描边或轻微透明度，不改变按钮位置、点击范围或页面布局。
- 将快速反馈、面板展开与关闭、站牌显隐等非滚动动画收束为少量可复用的 motion
  token；它们服务于「发生了什么」和「下一步在哪里」，不为装饰而播放。
- 路线列车仍严格由滚动进度决定。M3 式的缓动或物理感只可用于点击后的即时反馈，不能让列车弹跳、追赶用户滚动、擅自补间到下一站或制造假的实时运行感。
- 续行中的 QQ 门户群入口可以拥有明确的按压与焦点反馈，但外形仍是站内导视的一部分，而不是脱离叙事的圆角 M3 主按钮或悬浮 FAB。
- 移动端以可触及的目标尺寸、清楚的焦点与按压反馈、随空间调整的信息密度为优先；不照搬 M3 的导航栏、导航轨或多 pane 应用骨架。
- `prefers-reduced-motion`
  下保留状态可见性和内容层级，以即时但不突兀的状态切换代替位移、缩放、逐帧线路绘制与物理感动效。

### 主线与支线

- **服连快线（Serverlink）是首页前半程的主线。**
  它的列车装饰沿一条连续联络线经过世界引入与三个子服务器的介绍，使「三个服务器构成一个 Fetarute」成为能被看见的结构。
- 每个子服务器拥有自己的停靠段落：只介绍它在整体中的位置、气质、代表性场景和与其他部分的关系；不在首页写玩法细节、命令或加入操作。
- **同岸是服连快线与湾岸支线的叙事换乘站。**
  换乘把首页关注点从服务器结构交给玩家社群；湾岸支线继续经过同岸正文，并在续行把读者送往其他页面。
- 同岸之前的其他章节可以使用各自的线路装饰作为局部标记或支线，但不能提前切断 Serverlink，也不能被误读成另一条把三个子服务器连在一起的联络线。
- 线路色与名称承载真实语义。线路的正式中英文名、代码、品牌色与叙事站序统一读取
  `src/data/`，页面不得复制或临时臆造另一套值。

### 滚动中的关系

这组动效由三个概念组成：**scroll-driven animation** 控制进度，**line drawing**
让 SVG 轨道随阅读逐段显现，**continuity transition** 让同一列车在相邻章节之间保持身份与方向。

```text
到站实景
  ↓ Serverlink 主线开始
联络线：为什么三个子服务器是一体
  ↓ 三服汇连续停靠
创造服 → 大厅服 → 生存服
  ↓ Serverlink 抵达同岸
换乘湾岸支线：共同建设与玩家社群
  ↓ 短距离接续
续行：真实地图 / Wiki / QQ 门户群
```

- 列车位置应随实际滚动进度平滑 `translate`，而不是自动循环行驶、跳到下一站或表现为实时运行状态。
- 每次经过一个子服务器章节，可用站名牌和构图留白形成可读的停靠感，但列车位移始终由用户滚动驱动；离开时才让下一段轨道出现。内容本身不需要跟随列车移动。
- 桌面端允许主线在章节之间横向或斜向转折；移动端应收束为页面边缘的纵向轨道，保证阅读方向与触控空间。
- 视觉上可让轨道从首屏到站画面驶出，在同岸明确换乘，最终抵达续行出发厅；真实地图、Wiki 与 QQ 门户群因此成为可选择的下一程，而非突兀按钮。

### 扁平列车与线路

首页的列车和轨道延续启动动画的**扁平导视 UI**，而不是转成写实铁路插画、等距地图或 3D 漫游。它应让读者感觉开屏里驶过的同一班 Serverlink 列车继续在页面的线路图上前进，并在同岸通过另一班湾岸支线列车完成可见换乘。

- 列车使用简洁的二维几何：实体车身、由背景色挖出的车窗、清晰的 1px 结构边；不画车头透视、车轮细节、金属高光、体积阴影或烟雾。
- 主线使用有明确方向的单一色带／线路图路径；以水平、垂直和受控的 45° 或 90° 转折表达连接关系，不使用消失点、枕木透视或逼真轨道材质。
- 读者滚动时，列车沿当前服务线路以二维 `translate`
  前进，已走过的线段保持可见；这是开屏「列车驶过色带」的可阅读、可停靠版本，不是自动播放的背景动画。
- 每个子服务器章节的停靠点使用平面站名牌和短色带。其他线路可以从该停靠点分出，作为该 section 的局部导视；它们应在离开章节时视觉上回接 Serverlink 主线。
- 章节内容维持开放的阅读网格，列车与线路作为不设外框的独立导视层穿行于内容之间；它们不能遮挡标题、正文、链接、焦点样式或触控目标。

建议把页面末尾做成**续行出发厅**而非汇总卡：列车短暂停靠，首页叙事结束，真实地图、Wiki 与 QQ 门户群成为清楚标注的下一程。底部只保留低矮站台 Footer，探索线继续贯穿页面底边；收束感来自整趟连续行程，而不是再叠加一屏导航。

### 不变的边界

- 保持原生滚动，不使用整屏强制翻页或滚动速度限制。续行 PIDS 只在第一次向下意图时把固定屏幕从目的地切到帮助，并短暂停留以保证翻页可见；持续输入会自动恢复原生滚动，已经停下的读者也可用下一次输入继续前进。
- 不复制 Portal 的固定壳层、页面边框、分栏容器或卡片化 section 节奏；首页的边界来自内容与留白，不来自包围它们的 UI 框架。
- 线路和列车是叙事装置，不显示虚假的列车班次、实时位置、里程或服务状态。
- `prefers-reduced-motion`
  下仍完整展示各段内容与线路关系，但停止逐段绘制和列车位移；不能让减少动态的读者失去结构信息。
- 动画只使用可组合的 `transform` 与
  `opacity`；轨道绘制应有静态回退，避免加载或低性能设备使阅读中断。
- 禁止 3D 透视、视差、拟物材质、玻璃浮层、发光粒子或持续循环的列车运动；这些都会打断启动动画已经建立的平面导视感。

### 00 · 启始湾：抵达 Fetarute

**读者需要知道：** 我来到哪里？

- 承接开屏的线路导视、站牌与到站实景，以「欢迎来到 Fetarute」建立抵达感。
- 用极短的文字说明 2017 年的起点，以及这里是一座仍被持续建设的 Minecraft 社区。
- 开屏承担全页最完整的叙事仪式；首屏保持安静，不堆叠地址、版本、服务器状态或多个行动按钮。

### 01 · 看见一座被连接起来的世界

**读者需要知道：** 铁路在 Fetarute 中意味着什么？

- 用少量代表场景说明铁路如何连接地点、建筑、记忆与人，而不把首页写成建设史或铁路资料库。
- 清楚交代三个子服务器并非彼此孤立：服连快线（Serverlink）运营它们之间的联络线，使整个 Fetarute 成为可抵达、可穿行的整体。
- Gallery 负责建立世界的空间与气质；图片标题保持具体，完整历史、作者资料与更多相册交给社区页。
- 这一段是轻量引入，不罗列线路全表、站序、地图功能或服务器机制。

### 02 · 三服汇：轻量认识三个子服务器

**读者需要知道：** 三个子服务器分别为整体带来了什么？

- 以一个连续章节完成创造服、大厅服与生存服三次停靠；每次只给出名称、角色定位、一句简介和少量代表场景。
- Serverlink 列车在三个 Station
  Mark 之间保持连续，局部地图只作为用户主动打开的场景补充，不扩写为首页信息面板。
- 介绍只回答「这里在 Fetarute 整体中的意义是什么」。玩法、命令、地址、状态和完整地图入口由信息页承接。

### 03 · 同岸：看见共同生活的人

**读者需要知道：** 这座世界为什么不只是一张地图？

- 同岸是首页的社群章节，也是服连快线与湾岸支线的明确换乘站；它把叙事重心从服务器结构转向玩家留下的生活与建设痕迹。
- 主故事固定为
  **SURcentral 系统改建**：从旧系统接近饱和、SUR100 系列列车重新设计，到玩家共同规划海岛线与大都会线并建设整个系统。结尾必须明确它只是众多故事中的一个，避免把单一工程写成社群全貌。
- 「共同经历」由
  **2026 跨年纪念**与两次线路试车组成；每次载入随机显示一条并避开刚展示的片段，以一张画面和极短叙事说明玩家如何一起度过具体时刻，不扩写成活动回顾长文。
- 「一直在场」准备多条可核实的日常贡献故事；每次载入随机显示其中一条并避开刚展示的故事。它表达玩家在维护、建设、记录等日常里的持续参与，不自动轮播，也不制造排行榜。
- **待完成：**
  后续补充一条经过核实的「欢迎或帮助后来者」故事，确认玩家、具体行动、图片与公开许可后再进入随机池；首页暂不发布虚构占位故事。
- 展示对象是玩家留下的作品、关系与记忆，不制作头像、在线状态与数据组成的全员玩家格，也不把少数玩家包装成排行榜。
- 已确认玩家的方形头像直接与正文中的姓名同行，不再在主故事末尾重复一整块署名；完整玩家故事、活动记录、相册与 credits 进入社区页。
- 推荐价值主张：**「服务器让我们相遇，玩家让这里成为一个世界。」**

### 04 · 续行：前往更多页面

**读者需要知道：** 首页到站后，我还能去哪里？

- 续行由一屏以内的文字邀请与固定出发厅组成，不是新的长篇叙事章节，也不是通用卡片宫格。
- PIDS 第一页展示可确认的站名或世界地图入口；第二页承接首次到访帮助、QQ 门户群号与二维码。两页只替换屏幕内部内容，不能让 PIDS 外框随换页移动。
- 右侧方向牌优先提供 Wiki，并以明确的「施工中」项目为未来页面保留位置；没有真实地址的社区、状态等入口不得伪造为可用导航。
- 推荐表达：**「在这里到站，也从这里出发。选一个感兴趣的世界，下一段旅程即刻启程。」**
- 探索线贯穿页面底部，表示旅程仍在继续；续行后只允许一条低矮、非目录式的站台 Footer，不能追加公告列表、状态面板或另一屏导航。

## 页面职责分工

### 首页

- 用开屏与连续铁路行程介绍 Fetarute 的身份、世界结构和社群气质。
- 只提供足以产生兴趣的代表性场景与玩家片段，不承担资料完整性。
- 以续行完成对真实地图、Wiki 与 QQ 门户群的导流；未完成的独立页面只保留施工中提示。

### 社区页

- 承接完整玩家故事、社区活动、共同建设记录、相册与 credits。
- 允许内容持续增长，不以「必须展示所有玩家」作为发布前提；所有公开姓名、作品与引语均需确认来源和展示许可。
- 解释社区如何参与和联系，并保留 QQ 门户群作为当前有效入口。

### 信息页

- 集中展示服务器状态、当前在线玩家、公告、地图入口与经确认的服务器资料。
- 后续规则、指南、版本和加入要求通过 Astro Content Collections 维护，并从信息页进入。
- 状态与在线玩家必须明确数据时间和失败状态，不能让缓存或缺失数据看起来像实时事实。

## 不应放入首页的内容

以下内容并非不重要，而是应在正式、可维护的独立页面或出口菜单中出现：

- 创造、生存、大厅等分区的玩法说明与游戏命令。
- Minecraft 版本、模组或客户端要求、服务器地址、白名单与审核细节。
- 实时在线人数、服务器运行状态、公告时间线、脱离世界上下文的通用地图入口与下载内容。三服汇可以在每个世界正文后提供一次按需 BlueMap：桌面端允许在车窗内启动，小屏只在新标签页打开，且都不得自动载入。
- 全员玩家头像格、在线排行榜、完整玩家档案与不断增长的社区相册；首页同岸只保留少量代表性片段及其必要的玩家身份提示。
- 线路全表、连续站序、站码与细致的铁路数据查询。
- Discord、X、在线申请等当前无效或未确认的加入入口。
